# Itemized Statements

This process is a replacement for the Sutherland RPA bot that printed itemized statements from IDX. 

## How it works
The input file is automatically generated by HCX and saved to the share drive location. The file consists of all patient requests for statements that are currently in the 120 work pool with an outstanidng status.


1. An input CSV with two columns, `HCENPTACCT` (invoice number) and `ZZACPAANSGROUP` (group number), is loaded into the `inputs` table.  
2. A **run** is created against that file. A file can have many runs; each run is one processing pass over the file.  
3. Each invoice is processed in its own transaction. The result is written to both `attempts` (immutable history) and `outputs` (latest result per invoice).  
4. Re-running the same file skips invoices that already succeeded and retries the rest.
5. Each workable invoice is then iterated through the selenium process to send the statement to the designated printer

## Usage

```bash  
# Process a file (skips invoices that have already succeeded)  
uv run itemized-statements [-d FILE_DATE] [-r] [--dry-run]
```

| Option | Description | Default |
| --- | --- | --- |
| -d, --file-date | Input file date in YYYYMMDD format. The bot reads {FILE_DATE}_PAANS_BOT_v2.csv. | Today's date |
| -r, --retry-failed-only | Only reprocess invoices that failed in a previous run. | False |
| --dry-run | Writes to the staging database and runs the workflow without actuall demanding the statement. | False |
| --headless | Runs seleneium in headless mode | False |
| -h, --help | Show the help message. |  |


## Functionality
- Raise `BusinessException` for expected, data-driven failures. Is not retryable 
- Raise `ApplicationException` for known exceptions. Is retryable
- Let any other exception propagate; it is recorded as an python exception.  
- Return normally for success.


## Database schema

### `runs`  
One row per processing pass over a file.

| Column | Notes |  
|---|---|  
| `run_id` (PK) | Start time as `YYYYMMDD_HHMMSS`. If that second is taken, `_2`, `_3`, ... is appended. |  
| `file_name` | Input file name |  
| `run_number` | 1, 2, 3... per file. Unique with `file_name`. |  
| `status` | `loaded`, `in_process`, `completed`, `failed` |  
| `start_time`, `end_time` | Naive local time |  
| `failure_reason` | Set only when the run itself fails |  
| `total_records` | Number of invoices selected for this run |  
| `created_at` | |

### `inputs`  
Raw CSV rows. Loaded **once per file**, not once per run.

| Column | Notes |  
|---|---|  
| `id` (PK) | |  
| `file_name` | Unique with `invoice_number` |  
| `invoice_number` | From `HCENPTACCT` |  
| `group_number` | From `ZZACPAANSGROUP` (blank becomes `NULL`) |  
| `row_number` | Position in the CSV |  
| `loaded_by_run_id` | FK to `runs` |  
| `loaded_at` | |

### `outputs`  
One row per invoice, ever. Holds the **most recent** attempt's result.

| Column | Notes |  
|---|---|  
| `invoice_number` (PK) | |  
| `first_file_name`, `first_seen_at` | The first file the invoice appeared on, taken from `inputs`. Never updated. |  
| `status` | `success` or `failed` |  
| `exception_type` | `business` or `application` |  
| `exception_reason` | Truncated to 4000 characters |  
| `start_time`, `end_time` | Latest attempt |  
| `run_id` | FK to `runs` (latest attempt's run) |  
| `group_number` | |  
| `attempt_count` | |  
| `updated_at` | |

### `attempts`  
Immutable history. One row per attempt per invoice, with the same result columns as `outputs`.

| Column | Notes |  
|---|---|  
| `attempt_id` (PK) | |  
| `invoice_number` | FK to `outputs`. Unique with `attempt_number`. |  
| `attempt_number` | 1, 2, 3... per invoice |  
| `file_name`, `run_id`, `group_number` | |  
| `status`, `exception_type`, `exception_reason` | |  
| `start_time`, `end_time`, `created_at` | |

## Processing flow

```  
close_stale_runs()    → fail any in_process runs older than 12 hours  
create_run()          → status: loaded  
register_input_file() → insert new rows into inputs  
start_run()           → status: in_process  
get_work_items()      → invoices still needing work  
  for each invoice:   
    process_invoice()   
    record_attempt()  → one transaction: INSERT attempts + upsert outputs  
complete_run()        → status: completed (or failed if a fatal error occurred)  
reconcile()           → verify outputs matches latest attempts  
```
